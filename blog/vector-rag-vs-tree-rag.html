RAG の検索方式

類似度で探すか、
目次で探すか

ベクトル検索 RAG類似度で検索。速い・安い・大量文書向き。
ツリー検索 RAG文書を目次ツリーにして LLM が辿る。長い 1 文書の位置特定向き。

仕組み

ベクトル検索 RAG

  1. 1固定長で分割章の境界を無視。文脈が切れる。
  2. 2埋め込みベクトル DB に保存。
  3. 3近傍検索上位 k 件。別年度の文(赤)も混入。
  4. 4回答根拠は類似度スコアのみ。

ツリー検索 RAG

例: PageIndex
  1. 1構造で分割章・節単位。チャンク分割なし。
  2. 2ツリー生成LLM が要約・ページ範囲付き JSON を作成。DB 不要。
  3. 3推論で探索LLM が枝を選んで下る。外れたら戻る。
  4. 4回答根拠は経路とページ番号。

選び方

ベクトル検索 RAG

  • 文書が数千件以上
  • 1 件が短く、構造なし
  • 速度・コスト優先

ツリー検索 RAG

  • 長い文書内の正確な位置が必要
  • 章立てがある
  • ページ番号の根拠が必要(監査・法務・金融)
